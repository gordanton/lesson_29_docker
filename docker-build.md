# Сборка и проверка образа

Приложение на Flask. Оно показывает, что контейнер запустился, и считает две операции: умножение и деление.

Команды ниже выполняйте в папке, где лежат `Dockerfile`, `app.py` и `requirements.txt`.

Перед сборкой Docker Desktop должен быть запущен. Проверка:

```powershell
docker version
```

В выводе должны быть и `Client`, и `Server`. Если `Server` нет — демон Docker не работает, сборка не начнётся.

## Собрать образ

```powershell
docker build -t lesson29-app .
```

- `-t lesson29-app` — имя образа (тег). По нему вы потом запускаете контейнер.
- `.` — контекст сборки: текущая папка. Docker отправляет её демону, а `COPY` в Dockerfile берёт файлы отсюда.

Образ — это шаблон. Сам по себе он ничего не запускает. Запущенная копия образа называется контейнером.

После любой правки `app.py` или `requirements.txt` образ нужно собрать заново. `docker run` берёт файлы из образа, а не из папки на диске.

## Запустить контейнер

```powershell
docker run --rm -p 5000:5000 lesson29-app
```

- `--rm` — удалить контейнер после остановки. Образ при этом остаётся.
- `-p 5000:5000` — проброс порта: порт 5000 на вашем компьютере ведёт на порт 5000 внутри контейнера. Слева — хост, справа — контейнер.
- Окно терминала останется занятым: сервер работает на переднем плане. Остановить его — `Ctrl+C`.

Проверка в браузере:

- [http://localhost:5000](http://localhost:5000) — сведения о контейнере
- [http://localhost:5000/health](http://localhost:5000/health) — `{"status": "healthy"}`
- [http://localhost:5000/multiply/6/7](http://localhost:5000/multiply/6/7) — `{"result": 42}`
- [http://localhost:5000/divide/10/2](http://localhost:5000/divide/10/2) — `{"result": 5.0}`

В адресе только целые числа. `/multiply/2.5/3` не сработает: маршрут ждёт целые. `/divide/10/0` делит на ноль: этот запрос завершится ошибкой, остальные адреса продолжат открываться.

## Запуск в фоне

```powershell
docker run -d --name lesson29 --rm -p 5000:5000 lesson29-app
```

- `-d` — фон. Терминал сразу освободится.
- `--name lesson29` — имя контейнера, чтобы не искать его по id.

```powershell
docker ps
docker logs lesson29
docker stop lesson29
```

`docker ps` показывает только работающие контейнеры. После `docker stop` контейнер с `--rm` исчезнет сам. Образ `lesson29-app` останется: его видно через `docker images`.

## Если порт занят

Ошибка `port is already allocated` значит, что 5000 на компьютере уже занят. Меняется только левый порт:

```powershell
docker run --rm -p 5001:5000 lesson29-app
```

Тогда открывайте [http://localhost:5001/multiply/6/7](http://localhost:5001/multiply/6/7).

## Два сервиса через Compose

`docker-compose.yml` поднимает Flask (`backend`) и страницу (`frontend`) в одной сети. Страница открывается на порту 8080. Порт Flask наружу не публикуется: браузер ходит только на frontend, а nginx внутри него пересылает адреса `/api/...` на `http://backend:5000`.

Сначала остановите одиночный контейнер, если он ещё занимает терминал (`Ctrl+C`). Затем из папки урока:

```powershell
docker compose up --build
```

Откройте [http://localhost:8080](http://localhost:8080). На странице видны ответ Flask и калькулятор. Умножение `6` и `7` должно дать `42`.

Остановка: `Ctrl+C`, затем

```powershell
docker compose down
```

`down` удаляет контейнеры этой связки. Образы остаются.
